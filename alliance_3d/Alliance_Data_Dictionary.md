# Alliance Yard GeoPackage: Data Dictionary

Source file: `Alliance_Project_Data.gpkg` (inspected 5 Oct 2026). 14 spatial layers plus the QGIS `layer_styles` table.
Fill = rows with a non-null value. **Add** = attribute that does not exist yet and is recommended.

## 1. Conventions (apply to every layer)

| Rule | Detail |
|---|---|
| CRS | Authoritative layers in **EPSG:32614** (UTM 14N, meters). Raw OSM `*_query` layers stay in 4326 as reference only. **`buildings` is in 4326 and should be reprojected to 32614.** |
| Keys | `fid` is the automatic primary key. Business keys are text and unique: `lot_id`, `track_id`, `crane_id`, ... |
| Foreign keys | Same value format everywhere. Today `lots.lot_id = 'LOTB'` but `parking_rows.lot_id = 'B'`, so they do not join. Use `LOTB` style. |
| Domains | One spelling per category, lowercase with underscores (see lot_type, track_type). |
| Real vs placeholder | Anything simulated gets `is_sim = 1`. Anything copied from OSM gets `source = 'osm'`. |
| Heights | `height_m` is numeric (REAL), never text. Required on every layer the 3D viewer extrudes. |

## 3. Layer specifications

### lots (Polygon)
| Attribute | Type | Fill | Rule |
|---|---|---|---|
| lot_id | TEXT | 13/13 | `LOTA`...`LOTJ`. Repeats for multi-part lots (A x2, G x2, J x3) |
| lot_name | TEXT | 13/13 | Display name, e.g. `B Lot` |
| lot_type | TEXT | 13/13 | Six spellings today (`container`, `Container`, `40' containers`, `chassis`, `Chassis`, `Broken Chassis`). Domain: `container`, `chassis`, `broken_chassis` |

### yard_surface (Polygon)
`name` (`Main floor`), `surface_type` (`pavement`). One polygon of about 3.98 km2. Split by `surface_type` (asphalt / concrete / gravel) later if you want surface detail.

### building_query (MultiPolygon, 4326): raw OSM, reference only
30 features, 21 columns. Only 13 have a `building` tag; the rest are landuse, water, or parking. Keep: `osm_id`, `name`, `building`, `building:levels`, `operator`. Promote real buildings into `buildings` with `source = 'osm'` and a numeric `height_m` (`levels x 3.5`, else a default by type).

### roads_query (LineString, 4326): raw OSM, mixed content
366 features, 49 columns, four kinds of feature in one table:

| Content | Count | Where it should go |
|---|---|---|
| `highway` (service 203, unclassified 15, residential 6, secondary_link 4, secondary 1, tertiary 1) | 230 | `roads` |
| `railway = rail` | 98 | `rail_osm` (reference; your `tracks` is the working layer) |
| `barrier` (fence, jersey_barrier) | 24 | `barriers` |
| power lines, tanks, reservoir, waterway | about 38 | Drop or keep as reference |

Keep for `roads`: `osm_id`, `name`, `ref`, `highway`, `service`, `surface`, `maxspeed`, `lanes`, `oneway`, `access`, `bridge`, `layer`. Add `width_m`. Drop the `tiger:*` columns and the sparse ones (`horse`, `bicycle`, `covered`, `cables`, ...).

## 5. Open questions (these change the generated geometry)

1. **`stall_angle = 30`**: measured from the row line, or from perpendicular? The exporter assumes from the row line, which gives about 2.2 m of width per stall at your 4.3 m pitch.
2. **Which side of each row do the stalls sit on?** The exporter picks the side with more lot area (left for all current rows). Add `stall_side` to make it explicit.
3. **Segment numbering**: rows 12 and 13 have two segments each. Are spots numbered continuously across the two?
4. **`gantry_paths.side = 'rise'`** and the `7201,7202` list: what do they mean?
5. **`cuts_crossing`**: what is it for?
6. **Imagery**: the guide lists a Google Satellite XYZ URL for QGIS. Google's terms do not permit that use of its tiles. The viewer uses Esri World Imagery, so check its terms before publishing anything.
